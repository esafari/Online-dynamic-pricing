Pricing Decision Service — project map

Every folder and file in this repository, in the order the request actually uses them

Start here

How to read this

This repository is one product: a Pricing Decision Service that answers “what price should we show this shopper, for this SKU, right now?” and then learns from that choice overnight. The Python that does the work lives under src/pricing_decision/. The knobs that change without a code edit live under configs/. What the service writes while it runs lives under data/. The browser lab you are looking at is FastAPI serving src/pricing_decision/web/index.html. Azure does not add a second codebase; it is a runbook in docs/ plus deploy scripts in infra/ that host this same package.

When you are lost, start at src/pricing_decision/api/app.py. That file is FastAPI. A live request hits POST /v1/price, which calls PricingOrchestrator.decide() in orchestrator.py, which walks stages 0 through 8. Overnight learning is the same orchestrator’s cousin, offline/pipeline.py, writing into data/lake/. To put the app on Azure you change adapters under services/, not the causal or bandit stages.

Ignore generated folders. .pytest_cache/ and src/pricing_decision_service.egg-info/ appear after you install or test; they are not source. A local .venv/ is your Python environment. None of those belong in the story of the product.

Repo root

Root files

pyproject.toml is how Python knows this is a package. It names the project pricing-decision-service, requires Python 3.11+, and lists FastAPI, uvicorn, pydantic, numpy, PyYAML, and prometheus-client. The optional dev extra adds pytest and httpx. The console script pds points at pricing_decision.cli:main. Setuptools is told to find packages under src/. Pytest is told to look in tests/ with src on the path.

README.md is the human on-ramp: the stage table, a venv install, pytest, a one-shot cli decide against examples/request.json, and the HTTP verbs for serve mode. It is not the Azure runbook; that is docs/azure-implementation.html.

Dockerfile copies pyproject.toml, README.md, src/, configs/, and examples/, installs the package, and starts uvicorn on pricing_decision.api.app:app at port 8080. That is the same process you run on the laptop. .dockerignore keeps tests, data, and caches out of the image. .gitignore keeps venv, pyc, and data noise out of git.

Python

src / the package

src/pricing_decision/ is the only Python package you maintain. __init__.py exports the version string FastAPI shows on /health. Everything else is a role: api speaks HTTP, web is the lab page, stages is the online pipeline, services talks to catalog and logs, core holds shared types, offline is the night shift, and a handful of modules at the package root glue those together.

config.py is the compass. ROOT is the Pricing folder. load_yaml("catalog.yaml") always reads from configs/. Settings takes environment variables prefixed PDS_ — host, port, whether Kafka is on, the log buffer directory, epsilon, the propensity floor. When you later point Redis or App Configuration at Azure, new settings land here, not in a stage file.

HTTP

FastAPI

The FastAPI application is src/pricing_decision/api/app.py. create_app() builds it; the module-level app = create_app() is what uvicorn loads. api/__init__.py re-exports create_app so tests can import it cleanly.

The home page GET / returns web/index.html. GET /azure returns the Azure runbook. GET /project returns this file. GET /health is the liveness probe. The public pricing contract is POST /v1/price; the body that comes back has price, badge, coupon, reason codes, and decision_id, never propensity. POST /v1/price:explain is the internal twin that does leak scores, and it must stay off the public internet in production. Batch, outcomes, offer redeem, CS lookup, control plane, stage playground, offline run, architecture JSON, and admin reload are all routes on this same app.

You start it with python -m pricing_decision.cli serve, or python -m uvicorn pricing_decision.api.app:app --host 127.0.0.1 --port 8080 --reload. Open http://127.0.0.1:8080/ for the lab. FastAPI’s own docs sit at /docs if you want the OpenAPI page.

Browser

Lab UI

src/pricing_decision/web/index.html is the single-page lab. The four (now five) top buttons are pipelines: Project, Azure, Architecture, Online PDS, and Offline learning. Left-nav buttons under each pipeline are stages loaded from YAML through the API. Online and offline stages POST to /v1/stages/run and /v1/offline/run. Azure and Project are iframes of the HTML files in docs/. There is no React build; it is one HTML file with fetch calls.

Hot path

Online stages

src/pricing_decision/stages/ is the checkout pipeline, one file per stage, numbered so the spec and the code stay aligned. __init__.py marks the folder as a package. You do not rewrite these files to “be Azure.”

stage0_ingestion.py validates the request, resolves the SKU in the catalog, and honors idempotency so a retried checkout does not mint a second decision. stage1_preprocess.py builds the feature vector: identity, consent, segment, and the raw x that later models see. If consent is off, the vector stays generic. stage2_guardrails.py drops illegal prices — MAP, floor, stock, frequency, budget — before anyone scores them. stage3_candidates.py turns what remains into a discrete arm ladder. Holdout collapses that ladder to list price only.

stage4_causal.py scores each surviving arm; the lab uses an S-learner that predicts expected margin. stage5_bandit.py is contextual Thompson sampling with an epsilon floor and a propensity floor so later OPE never divides by zero. stage6_postprocess.py charm-prices, binds a coupon, and applies stickiness so the same shopper and SKU can see the same offer again. stage7_logging.py writes the experience tuple, including propensity, without putting that tuple on the client response. stage8_response.py is the safe JSON the channel actually receives. stage9_fallback.py is the ladder used when a dependency is sick: you still return a price. stage10_cache.py holds the version pins (policy, causal model, guardrails) and supports hot reload.

Adapters

Services

src/pricing_decision/services/ is the seam you change when this lab becomes Azure. The orchestrator talks to these classes; the stages do not open files or sockets themselves.

catalog.py reads SKUs from configs/catalog.yaml today and will read Cosmos later. identity.py resolves a customer, guest, or anonymous id and the consent flag. feature_store.py is the in-memory map of feature vectors; Redis replaces it. coupon.py issues, looks up, and redeems offer codes; Cosmos becomes the ledger so a code still works after a policy change. control_plane.py holds the kill switch, merchandiser freeze, daily discount budget, and the sticky-price store; App Configuration and Redis take those jobs in production. logger.py appends JSONL under data/log_buffer/ and already knows how to speak Kafka when PDS_KAFKA_ENABLED is true. outcomes.py records purchase, refund, and return against a decision_id. gateway.py is the in-process stand-in for the product split that Front Door and API Management will own: what is public versus what is explain and admin.

Shared types

Core

src/pricing_decision/core/ is the vocabulary the rest of the package shares. models.py is pydantic: the inbound DecisionRequest, arms, scores, the client Offer, the full PricingDecision, and the DecisionContext that travels down the pipeline. exceptions.py is how an unknown SKU becomes HTTP 404 and a validation failure becomes 400. ids.py mints decision_id values. metrics.py is the in-process counter snapshot behind GET /metrics. tracing.py is the hook for request timing. None of this knows about Azure.

Night shift

Offline learning

src/pricing_decision/offline/ is the same product after checkout, when you are allowed to be slow. pipeline.py is the conductor: ingest, join, backfill, causal, bandit, OPE, registry, gate. lake.py reads and writes JSONL under data/lake/; that path becomes ADLS Delta later. ingest.py copies the live log buffer into the lake. seed.py can invent history so the lab has something to train on. join.py matches decisions to outcomes on decision_id with a reward window. backfill.py reconstructs features as of the decision timestamp, not “whatever is current.” reward.py turns a joined row into the scalar the models optimize.

causal.py trains the S-learner used online. bandit.py updates the policy. ope.py estimates IPS, SNIPS, and DR so you can score a new policy on old logs. fairness.py and drift.py are the gates that sit beside that estimate. registry.py writes data/registry/models.json; Azure ML replaces that file. gate.py decides whether a candidate is allowed to go near traffic. rollout.py is the shadow-then-canary story that Container Apps revisions will execute with traffic weights.

How it is wired

Glue code

orchestrator.py constructs every service and every stage, then decide() walks ingestion through response, catching failures into the fallback handler. decide_batch() is the campaign path. If you want to see the whole online story in one file, this is it.

playground.py powers the Online PDS tab: it can stop after a named stage so the lab can show arms or scores without finishing the request. platform.py powers Architecture: use cases from YAML, the monitor snapshot, CS lookup, the control-plane view. architecture.py loads the YAML that fills the Architecture, Azure, and Project left-navs.

cli.py is the command line. pds serve starts uvicorn. pds decide -f examples/request.json --explain runs one decision without a browser. That is the fastest way to prove the brain still works after you touch a stage.

Knobs

configs

YAML in configs/ is what the running process reads. Change a file and, for many of them, reload; you should not need a new function to add a SKU or flip a kill switch in the lab.

catalog.yaml is the demo merchandising world: Maya, James, Priya, Alex, Noah, and the SKUs including SKU-1234 at list 50. segments.yaml names those shopper types. features.yaml is the feature contract and TTLs. guardrails.yaml is MAP, floors, frequency, and budget. ladders.yaml is the discount arms. control_plane.yaml is kill switch, freeze, sticky TTL, and the daily cap. versions.yaml pins policy, causal model, and guardrail version. stages.yaml and offline_stages.yaml are the left-nav copy for the lab. use_cases.yaml is PDP, kill switch, sticky, budget, holdout, and the rest of the Architecture demos. architecture.yaml is layers, loops, and gaps. azure_architecture.yaml, azure_components.yaml, and azure_stages.yaml feed the Azure tab. project_map.yaml is the left-nav for this page.

What the lab writes

data

Nothing under data/ is the source of truth for how the product should behave; it is what a run produced. You can delete the JSONL files and the lab will recreate them the next time you score or train. Do not hand-edit them and expect the models to stay coherent.

data/log_buffer/decisions.jsonl is the live experience log, one JSON object per decide(), including propensity. That file is what Event Hubs replaces. data/lake/ is the local lakehouse: decisions.jsonl after ingest, outcomes.jsonl from checkout events, training.jsonl after join, backfill.jsonl after point-in-time features, plus causal_model.jsonl, bandit_model.jsonl, ope_report.jsonl, fairness_report.jsonl, and drift_report.jsonl. data/registry/models.json is the tiny model registry the gate reads. On Azure those paths become Event Hubs, ADLS, and Azure ML.

Proof

tests

tests/conftest.py builds a shared orchestrator fixture so each test does not re-parse every YAML file. The test_stage*.py files walk the online contract: ingestion, preprocess, guardrails and candidates, causal and bandit, response and logging. test_stage_playground.py hits the lab run API. test_offline_pipeline.py seeds, joins, and checks OPE. test_architecture.py is the net under the Architecture, Azure, and Project tabs — it asserts the HTML maps and the JSON catalogs still exist. From the Pricing folder, pytest should stay green after you change a stage. Azure integration tests, when you add them, belong here marked so they skip unless PDS_ENV starts with azure.

Around the package

infra, docs, scripts, examples

infra/azure-up.ps1 is the one-pass deploy: resource group, ACR, Container Apps, a printed HTTPS URL. infra/cli-kids.ps1 is the same first deploy with more prompting. Neither script rewrites Python. They host the Docker image of this package in Canada Central.

docs/azure-implementation.html is the Azure tab: components, architecture, CLI, phases. docs/project-map.html is this file. FastAPI serves both; you can also open them as files in a browser.

examples/request.json is a legal POST /v1/price body for the CLI. scripts/ holds one-off helpers that were used to generate pieces of the Azure HTML. They are not part of the runtime. You do not run them to price anything.
