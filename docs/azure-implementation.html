Overview

What this project is, and what Azure adds

The Pricing Decision Service answers a single operational question: given this shopper, this SKU, and this moment, what price should we show, and how do we learn from that choice later? That question is already implemented in this repository. A request is ingested, identity and features are resolved, guardrails drop illegal prices, a causal model scores what remains, a bandit selects an arm, a coupon is bound, the decision is logged with a propensity, and the client receives only a safe JSON body. Azure does not rewrite that sequence. It is the production platform around it: a place to run the process, remember features, store catalog and coupons, carry logs, train overnight, and freeze discounts without a new build.

On your laptop the same stages run in FastAPI with a YAML catalog, an in-memory feature store, and JSONL files. In Azure those adapters point at managed services in Canada Central so personal data stays in Canada. A public channel still calls POST /v1/price. Front Door terminates TLS and filters bots; API Management authenticates and rate-limits, and it keeps internal routes such as /v1/price:explain off the internet. Container Apps runs this FastAPI app with a p99 target under 100 ms. During that call the service reads online features from Redis and catalog or identity from Cosmos DB, applies guardrails, scores arms, picks one, and writes a redeemable offer. The shopper sees a price, a badge, a coupon, reason codes, and a decision_id. Propensity and model identifiers never leave on that response.

After the response, Event Hubs records the experience tuple of context, action, propensity, and versions without blocking checkout. A later purchase or refund is posted to the outcomes hub keyed by the same decision_id. Capture lands in ADLS. Offline jobs join those streams, reconstruct point-in-time features, train, and run off-policy evaluation. Azure ML registers a candidate only if that estimate beats the current policy and the fairness and drift gates pass. A new Container Apps revision is then opened in shadow, given a slice of traffic, and either ramped or rolled back. App Configuration can force list price on the next request if legal or merchandising needs an immediate freeze. App Insights is what tells you the new revision is slow or incomplete so you can send traffic back to the last good one.

Foundation

Start with a dedicated development subscription and the Entra directory that comes with it. That subscription is the billing and permission root; production pricing data should never live in a personal account. Sign in with az login and confirm you have Contributor. People use Entra to open the portal and the CLI; the Container App later uses a managed identity in the same directory so GitHub never holds a long-lived client secret. Create one resource group in Canada Central and put everything for this environment inside it, because deleting that group is how you stop paying. On the same day, set a Cost Management budget that emails you at a modest cap. A budget warns; it does not always shut resources off. Finally create a single Log Analytics workspace for the environment. Container Apps, App Insights, and later APIM should all write there. Several workspaces make simple questions impossible to ask.

Hosting

Azure Container Registry is the private shelf for Docker images of this app. Names are globally unique. Basic SKU is enough in development; production can move to Standard or Premium and, later, a replica in Canada East. A Container Apps environment is the cluster those images join, and you attach Log Analytics when you create it. The Container App itself is this FastAPI process: stages 0 through 10, a small CPU and memory footprint at first, replicas when traffic grows, and revisions so a new policy can take one percent of calls without replacing the old one. In development ingress can be external so you can open a browser; in production it should be internal behind API Management, and /v1/price:explain, /v1/control, and admin reload must never be on the public product. A Container Apps Job is the same codebase on a schedule for campaign lists. Do not fire thousands of single HTTP calls from Logic Apps with no backpressure. Do not begin on AKS or App Service. Container Apps is the host until you have a platform team and a scale problem that revisions cannot solve.

Config and secrets

Give the Container App a system-assigned managed identity and grant that identity roles, rather than baking Cosmos or Redis keys into environment variables. Key Vault holds the remaining secrets: Redis URL, Event Hubs send string, App Insights connection string, Cosmos key until you switch the SDK to Entra. Use RBAC on the vault, not a mix of access policies. App Configuration is the live rulebook that used to be control_plane.yaml and versions.yaml: kill switch, merchandiser freeze, policy and model pins, daily discount budget. Those flags must refresh in seconds. If App Configuration cannot be read, fail closed to list price using a cache no older than a minute. Free SKU is fine in development; production wants Standard and a replica in Canada East.

Online data plane

Two stores sit on the request. Redis, on TLS port 6380, is the millisecond cache that replaces the in-memory feature store and sticky-price map. Keys are short-lived: features, a sticky offer for shopper and SKU, frequency caps, and an incremented discount budget. If Redis is unavailable you still return a price from coarser defaults, because checkout cannot wait. Basic C0 is enough to learn the adapter; production should be Premium, zone redundant, and private. Cosmos DB is the system of record that replaces catalog.yaml, identity profiles, the coupon list, and decision lookup. Use separate containers partitioned on sku, customer_id, offer code, and customer_id again for decisions. Serverless is the right development SKU. Production should autoscale, back up, and fail over to Canada East. A coupon in Cosmos is a promise: a later policy change must not void a code already shown.

Streaming and lakehouse

Decision logs are telemetry, not a command queue, which is why Event Hubs with Kafka enabled replaces the JSONL buffer and Service Bus does not. One hub, pricing.decisions.v1, receives every decide() with propensity, policy id, candidate-set version, and experiment variant. Another, pricing.outcomes.v1, receives purchase, refund, and return keyed by decision_id, joined later on a seven-day window net of refunds. Joining only on customer_id will mix people and ruin OPE. Schema Registry versions that JSON so a silent field drop cannot poison training. ADLS Gen2 with hierarchical namespace is the lake: bronze for raw capture, silver for joined point-in-time rows, gold for OPE and campaigns. A plain blob account without HNS will fight Spark. Event Hubs Capture writes bronze on a timer so you do not need a custom consumer on day one. Keep capture in the same region. If the hub is down, buffer locally and stop exploring until it returns, or the propensities you log will be fiction.

Machine learning

Training never runs inside the online Container App. Azure ML is the workspace that replaces data/registry/models.json and laptop jobs: you submit causal, bandit, and OPE work, keep lineage, and register a model only when OPE beats the current policy and fairness and drift are acceptable. Serverless compute is enough for the numpy learners in this repo. A GPU cluster is a later choice and a common way to leave money running overnight. When joins no longer fit a single node, Microsoft Fabric or Azure Databricks in Canada Central reads the same ADLS paths that offline/join.py and backfill.py use today. The standing risk is training on “current” features instead of the values as of the decision timestamp.

Public edge

Skip Front Door and API Management until a real channel is calling you. Then Front Door Premium is the anycast door with TLS, bot manager, origin health, and a Canada POP. Point it at APIM or the app, never at the explain endpoint. Put the WAF in Detection for a week, then Prevention, with an allowlist for partner IPs. API Management is the product split that used to live in gateway.py: public price, checkout outcomes, CS lookup, and an internal product for explain and control. Developer SKU has no SLA; production should be Standard v2 or Premium on a VNet.

Observability and rollback

A bandit you cannot measure is just random prices. Application Insights, created against the same Log Analytics workspace, replaces in-process counters for production: duration of /v1/price, calls out to Redis and Cosmos, exceptions. Do not log propensity or PII in custom events; decision_id is enough on the public path. Metric alerts and an action group with a named owner fire on slow p99, 5xx, a gap between requests and Event Hub ingress, a stale kill switch, or a fairness gap. A workbook later fills the role of the lab Monitor tab: reward versus predicted value, propensity PSI, segment price gaps, logging completeness. Sampled telemetry makes those charts lie.

Security and Canada

In production, Redis, Cosmos, Key Vault, Storage, and Event Hubs should not have public endpoints. A VNet, private endpoints, and Container Apps integration are required, and DNS must be in place or the app will hang on names. Purview scans ADLS, classifies PII, and is how you show PIPEDA evidence that bronze decisions are not a free-for-all. Protected attributes used for audit must never enter the feature vector. Defender for Cloud watches for a public Cosmos account, Redis without TLS, and vulnerable images in ACR. Do not ship an image the registry has already flagged.

CI/CD

GitHub Actions with Entra OIDC is how a commit becomes a revision: tests, image, push to ACR, Container Apps update. Failed pytest must not deploy. Do not put AZURE_CLIENT_SECRET in GitHub. Federate the app registration and use azure/login with the federated token.

What to leave alone

AKS is a later host if Container Apps and a platform team cannot meet a sustained ten thousand decisions a second with a mesh you truly need. App Service slots are not a substitute for a propensity-logged canary. Service Bus is fine for occasional commands, not for this telemetry. Azure Communication Services is optional if you have no email provider; even then, never send a price that is not already in the offer ledger.

Architecture

How the pieces sit together

A shopper on web, app, email, or a till never talks to Python directly. The call arrives at Front Door, which is the public door: TLS, geography, and a WAF that should absorb bots so the bandit does not waste exploration on scrapers. API Management sits behind that door and decides who may ask for a price. The product that channels use exposes POST /v1/price and nothing that leaks scores. Explain, control, and admin stay on an internal product.

The work itself runs on Container Apps. Azure Container Registry holds the Docker image of this repo; the app is a replica of that image, scaled out if the line gets long, and versioned as revisions so you can send one percent of traffic to a new policy without replacing the old one. While a request is in flight, App Configuration is the live rulebook for kill switch, freeze, and version pins, and Key Vault is where connection strings live. The process authenticates to both with a managed identity rather than a password in an environment variable.

Two stores are on the hot path. Redis is the desk cache: feature vectors, a sticky price for the same shopper and SKU, frequency caps, and a running discount budget, all with TTLs measured in seconds or minutes. If Redis is down you still answer, using coarser defaults, because checkout cannot wait. Cosmos DB is the cabinet of record: list price, MAP, cost, stock, the identity graph and consent flag, the coupon ledger that must still redeem after a policy change, and the decision row a CS agent looks up by decision_id.

Once a price has been returned, logging must not sit on the critical path. Event Hubs, with Kafka enabled so the existing topic design still makes sense, carries pricing.decisions.v1 and pricing.outcomes.v1. Every decision event includes propensity and the version pins; without that, off-policy evaluation later is guesswork. Capture writes those events into ADLS Gen2 as bronze files. Nightly jobs turn bronze into silver training rows with point-in-time features, then gold OPE reports. Azure Machine Learning is where those jobs run and where a model is registered only if OPE, fairness, and drift agree. App Insights watches latency and completeness so a bad revision can be given zero traffic. All of that data plane stays in Canada Central; Canada East is for disaster recovery, not for cheaper training.

This repo Azure -------------------------- -------------------------------- FastAPI :8080 → Container Apps gateway.py → Front Door + APIM feature_store.py → Redis catalog.yaml + identity → Cosmos DB control_plane.yaml → App Configuration coupon / sticky → Cosmos offers + Redis TTL decisions.jsonl → Event Hubs data/lake/*.jsonl → ADLS Gen2 offline/pipeline.py → Azure ML jobs models.json → Azure ML registry metrics.py → App Insights

1. What this project becomes on Azure

Every local piece has one production home. Keep this picture in mind while you build; it is the target, not a catalog of extras. A shopper on web, app, email, a till, or a partner never talks to Python. The lab UI stays the same app, on internal ingress only, because /v1/price:explain must not face the internet.

Wire it in Python (do this in the repo)

Replace the in-memory flags in services/control_plane.py with App Configuration feature flags:

# pip install azure-appconfiguration azure-identity azure-keyvault-secrets
from azure.identity import DefaultAzureCredential
from azure.appconfiguration.provider import load, WatchKey
from azure.appconfiguration.provider import AzureAppConfigurationKeyVaultOptions

credential = DefaultAzureCredential()
config = load(endpoint=os.environ["PDS_APPCONFIG_ENDPOINT"], credential=credential,
              feature_flag_enabled=True, refresh_on=[WatchKey("pds.kill_switch")])

kill = bool(config["feature_management"]["pds.kill_switch"])  # shape depends on provider

7. Redis — online features + sticky prices

This replaces FeatureStore and StickyPriceStore. A feature GET should finish in well under two milliseconds. Create the cache with TLS only, then put the connection string in Key Vault rather than on the Container App as a raw environment secret.

Keys are short-lived and named so you can find them in a hurry. Feature vectors live at feat:{customer_id} with the TTL from features.yaml, often five minutes. Phase 8

10. Offline learning on Azure ML + Spark

Do not train on the Container App. Nightly jobs map one-for-one onto offline/pipeline.py. Ingest turns Event Hub capture into Delta bronze on ADLS. Join matches decisions to outcomes on decision_id with a seven-day reward window net of refunds, and writes silver training rows. Backfill reconstructs features as of the decision timestamp, not “current.” Causal training is an Azure ML job (the numpy S-learner in this repo first, EconML later). The bandit job writes a policy artifact. OPE computes IPS, SNIPS, DR, a bootstrap interval, and effective sample size into gold/ope. The registry step registers a model only if the DR estimate of the new policy beats the current one by the threshold, ESS is healthy, the fairness gap is under five percent, and max PSI is under 0.2. The gate then opens a new Container Apps revision at zero traffic — shadow — before any shopper sees it.

az extension add -n ml

Phase 10

12. Monitor, fairness, rollback

A bandit you cannot measure is just random prices. Create Application Insights against the same Log Analytics workspace you attached to Container Apps, then pass the connection string into the app. Instrument FastAPI with OpenTelemetry toward Azure Monitor. You can keep the in-process Prometheus counters for the lab, but App Insights is what production paging will use.

Before you take the bandit live, those alerts have to exist with a named owner. If p99 of /v1/price sits above 100 ms for five minutes, page on-call and scale replicas. If availability drops under 99.9 percent or 5xx crosses one percent, put all traffic on the last known-good revision. If Event Hub ingress lags request count by more than a tenth of a percent, force exploit so you stop exploring into an incomplete log. If rolling hourly revenue falls far below predicted value, freeze discounts and investigate. If propensity PSI crosses 0.2, stop exploring and retrain. If a protected-group price gap exceeds five percent, turn the kill switch on. If the kill switch flag cannot be read, fail closed to list price.

Phase 12

15. PIPEDA / Law 25 / fairness (Canada)

Every store that holds shopper or decision data is created in Canada Central. Confirm it with az resource list -g $RG --query "[].{n:name,l:location}" before you call this production. Consent already exists in preprocess: if the flag is off, the service sends a generic feature vector. Protected attributes such as exact age, gender, or ethnicity may live in a locked Cosmos container for audit and must never enter the feature vector; Azure Policy can deny unexpected columns in the training Delta table. In production, Key Vault and the data plane sit behind private endpoints, and public networks on Cosmos, Redis, and Storage are off. Retention in control_plane.yaml is 400 days; set Event Hub and ADLS lifecycle to match, then purge. Microsoft Purview scans ADLS, classifies PII, and is how you show that bronze decisions are not a free-for-all.

Failure

20. Azure fallbacks (same ladder as the lab)

Checkout still needs a price when a dependency is sick, so the ladder is the same one you already coded, just aimed at Azure names. If Redis is down, serve a segment-level default feature vector, mark the call degraded, and still return a price. If Cosmos is down, use the catalog warmed into replica memory at boot; if that is cold, fall back to a static list price. If the causal model times out, reuse last scores in Redis, or the rule-based ladder. If Event Hubs is down, write the local buffer (or a blob) and switch to exploit only so you do not explore into a log you cannot keep. If App Configuration cannot be read, fail closed when the last known flag was kill, otherwise use cached flags no older than a minute. If APIM or Front Door is unhealthy, origin probes fail over to a second Container Apps environment in Canada East in production.
