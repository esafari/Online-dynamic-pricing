Implement this project on Amazon SageMaker

Canada · same OfflinePipeline · train and OPE only · FastAPI still serves /v1/price

Read this first

What SageMaker is in this project

SageMaker is the night shift. It replaces the laptop jobs in offline/pipeline.py and the file data/registry/models.json. It does not replace FastAPI. A shopper still hits POST /v1/price on Container Apps or ECS. Guardrails, the S-learner, and Thompson sampling still run in-process in that container. SageMaker reads yesterday’s decisions and outcomes, joins them, reconstructs point-in-time features, trains, runs off-policy evaluation, and is allowed to register a challenger only if that estimate beats the current policy.

Do not put checkout on a SageMaker real-time endpoint on day one. That endpoint is a later option if μ ever leaves the container. For this repo, the artifact SageMaker produces is a version pin (causal_model_id, policy_id) plus files the online cache can load. You change offline/lake.py to read S3 and offline/registry.py to talk to the SageMaker Model Registry. You do not rewrite stage4_causal.py or stage5_bandit.py.

Create every bucket, job, and registry in ca-central-1 so shopper and decision data stay in Canada. Do not train in us-east-1 because the instance looks cheaper.

The mapping

Local job → SageMaker

The Offline learning tab is the contract. Each left-nav stage there is one SageMaker step. Ingest and join become Processing jobs that write bronze then silver. Backfill is a Processing job that writes silver features as of the decision timestamp. Causal and bandit become Training jobs. OPE, fairness, and drift are Processing jobs that write gold reports. Registry plus gate is a Model Registry package plus a condition step. Rollout is not a SageMaker deploy of the FastAPI app; it is the online host taking a new pin after the gate says yes.

This repo SageMaker (ca-central-1) -------------------------- -------------------------------- data/lake/*.jsonl → s3://pds-lake-…/bronze|silver|gold data/log_buffer/ → already captured to S3 / Kinesis offline/ingest.py → Processing: ol_ingest offline/join.py → Processing: ol_join offline/backfill.py → Processing: ol_backfill offline/causal.py → Training: ol_causal offline/bandit.py → Training: ol_bandit offline/ope.py → Processing: ol_ope offline/fairness.py + drift → Processing: ol_fairness, ol_drift data/registry/models.json → SageMaker Model Registry offline/gate.py → Pipeline condition (register or stop) offline/rollout.py → ECS / Container Apps traffic, not SM endpoint Dockerfile → ECR image the jobs run

Step 2

S3 lake

Create one bucket in Canada for this environment. Hierarchical prefixes replace the local files: bronze is raw capture, silver is joined and backfilled rows, gold is OPE and campaign reports. Block public access. Turn on default encryption. This bucket is the lake LakeHouse will point at once you swap offline/lake.py.

$Region = "ca-central-1"
$Account = aws sts get-caller-identity --query Account --output text
$Bucket = "pds-lake-$Account-dev"
aws s3api create-bucket --bucket $Bucket --region $Region --create-bucket-configuration LocationConstraint=$Region
aws s3api put-public-access-block --bucket $Bucket --public-access-block-configuration BlockPublicAcls=true,IgnorePublicAcls=true,BlockPublicPolicy=true,RestrictPublicBuckets=true
aws s3api put-bucket-encryption --bucket $Bucket --server-side-encryption-configuration '{\"Rules\":[{\"ApplyServerSideEncryptionByDefault\":{\"SSEAlgorithm\":\"AES256\"}}]}'

aws s3api put-object --bucket $Bucket --key bronze/decisions/
aws s3api put-object --bucket $Bucket --key bronze/outcomes/
aws s3api put-object --bucket $Bucket --key silver/training/
aws s3api put-object --bucket $Bucket --key silver/backfill/
aws s3api put-object --bucket $Bucket --key gold/ope/
aws s3api put-object --bucket $Bucket --key gold/fairness/
Write-Host "BUCKET=$Bucket"

Save the bucket name. You will pass it into every job as an environment variable PDS_LAKE_URI=s3://$Bucket.

Step 3

IAM role the jobs assume

SageMaker jobs do not use your laptop access key. They assume a role that can read and write the lake, pull the ECR image, and write CloudWatch logs. Create that role once. Later you attach the same role to the Pipeline.

$Trust = '{"Version":"2012-10-17","Statement":[{"Effect":"Allow","Principal":{"Service":"sagemaker.amazonaws.com"},"Action":"sts:AssumeRole"}]}'
aws iam create-role --role-name pds-sagemaker-dev --assume-role-policy-document $Trust
aws iam attach-role-policy --role-name pds-sagemaker-dev --policy-arn arn:aws:iam::aws:policy/AmazonSageMakerFullAccess
# Tighten later: S3 on $Bucket only, ECR pull, CloudWatch Logs, no * .
$RoleArn = aws iam get-role --role-name pds-sagemaker-dev --query Role.Arn --output text
Write-Host "ROLE=$RoleArn"

AmazonSageMakerFullAccess is acceptable in a throwaway dev account so the first job runs. Before anything that looks like production, replace it with a bucket-scoped policy. Do not put AWS_SECRET_ACCESS_KEY in a training script.

Step 4

Build the image SageMaker will run

The jobs should execute the package you already have, not a notebook rewrite of the S-learner. Build the existing Dockerfile, push it to ECR in Canada, and that image becomes both the online host (ECS) and the offline worker (SageMaker). Processing and Training jobs will call python -m into offline.pipeline.

aws ecr create-repository --repository-name pds-api --region $Region
aws ecr get-login-password --region $Region | docker login --username AWS --password-stdin "$Account.dkr.ecr.$Region.amazonaws.com"
docker build -t pds-api:local .
docker tag pds-api:local "$Account.dkr.ecr.$Region.amazonaws.com/pds-api:v0.1.0"
docker push "$Account.dkr.ecr.$Region.amazonaws.com/pds-api:v0.1.0"
$Image = "$Account.dkr.ecr.$Region.amazonaws.com/pds-api:v0.1.0"
Write-Host "IMAGE=$Image"

SageMaker must be allowed to pull that repository. If the first job fails with an image-pull error, add a repository policy that lets sagemaker.amazonaws.com and the role you created pull pds-api.

Step 5

Put data on S3

Two ways to get a lake SageMaker can see. The fastest is to run Offline learning locally so data/lake/ fills, then sync those files. The production way is Kinesis or MSK writing bronze directly; you can do that after the first job succeeds.

# After you have run Offline → Ingest / Join / Backfill in the lab:
aws s3 sync data\lake s3://$Bucket/silver/local-seed --region $Region
aws s3 cp data\log_buffer\decisions.jsonl s3://$Bucket/bronze/decisions/decisions.jsonl --region $Region
aws s3 ls s3://$Bucket/ --recursive

Until lake.py reads S3, a job can download the prefix to /opt/ml/processing/input (SageMaker mounts it) and write outputs to /opt/ml/processing/output, which lands back on S3. That is enough for the first pass. The adapter change is: if PDS_LAKE_URI starts with s3://, read and write there; otherwise keep today’s JSONL path so pytest still passes on a laptop.

Step 6

Processing jobs — ingest, join, backfill

A Processing job is a container that starts, runs one command, writes files, and dies. That is ol_ingest, ol_join, and ol_backfill. Create a tiny entry script once (you can keep it as the command string for the first week). Run ingest first, then join, then backfill. Do not train on “current” features.

$Image = "$Account.dkr.ecr.$Region.amazonaws.com/pds-api:v0.1.0"
$RoleArn = aws iam get-role --role-name pds-sagemaker-dev --query Role.Arn --output text

# Ingest + seed so the lake is not empty
aws sagemaker create-processing-job --region $Region --processing-job-name "pds-ingest-$(Get-Date -Format yyyyMMddHHmm)" `
  --role-arn $RoleArn `
  --app-specification "ImageUri=$Image,ContainerEntrypoint=python,ContainerArguments=-c,from pricing_decision.offline.pipeline import OfflinePipeline; from pricing_decision.orchestrator import PricingOrchestrator; OfflinePipeline(PricingOrchestrator()).run('ol_ingest', {'seed_n': 200})" `
  --processing-resources "ClusterConfig={InstanceCount=1,InstanceType=ml.m5.large,VolumeSizeInGB=20}" `
  --processing-output-config "Outputs=[{OutputName=lake,S3Output={S3Uri=s3://$Bucket/silver/after-ingest,LocalPath=/opt/ml/processing/output}}]"

Watch the job until it is Completed. Then create the same shape of job for ol_join and ol_backfill, pointing the input at the previous output prefix. In the console: SageMaker → Processing → the job name → CloudWatch logs. If Python cannot import pricing_decision, the image was not this repo.

When you are ready to stop pasting one-liners, save infra/sm-process.json and reuse aws sagemaker create-processing-job --cli-input-json file://infra/sm-process.json. The important part is the stage name you pass to OfflinePipeline.run.

Step 7

Training jobs — causal and bandit

Training jobs are the same idea with a model directory. ol_causal writes the S-learner artifact; ol_bandit writes the policy posterior. Use a small CPU instance. A GPU is unnecessary for the numpy learners in this repo and is a common way to leave money running overnight.

aws sagemaker create-training-job --region $Region --training-job-name "pds-causal-$(Get-Date -Format yyyyMMddHHmm)" `
  --role-arn $RoleArn `
  --algorithm-specification "TrainingImage=$Image,TrainingInputMode=File" `
  --hyper-parameters "stage=ol_causal" `
  --input-data-config "ChannelName=training,DataSource={S3DataSource={S3DataType=S3Prefix,S3Uri=s3://$Bucket/silver/backfill,S3DataDistributionType=FullyReplicated}}" `
  --output-data-config "S3OutputPath=s3://$Bucket/gold/models" `
  --resource-config "InstanceCount=1,InstanceType=ml.m5.large,VolumeSizeInGB=20" `
  --stopping-condition "MaxRuntimeInSeconds=3600" `
  --environment "PDS_LAKE_URI=s3://$Bucket"

The container must honor SageMaker’s paths or your own PDS_LAKE_URI. The first week, the easiest path is still OfflinePipeline(...).run("ol_causal") after the input channel is copied to the lake directory the code already knows. Repeat the job with ol_bandit. Do not start the online FastAPI process inside this job.

Step 8

OPE, fairness, and drift

A challenger you have not evaluated is just a new file. Run Processing jobs for ol_ope (estimator dr, then look at IPS and SNIPS too), ol_fairness, and ol_drift. Gold prefixes should contain JSON that says whether DR beats the current policy, whether the 95% interval still clears it, whether ESS is healthy, whether a segment price gap is under 5%, and whether propensity PSI is under 0.2. If those files are missing, the registry step must refuse.

aws sagemaker create-processing-job --region $Region --processing-job-name "pds-ope-$(Get-Date -Format yyyyMMddHHmm)" `
  --role-arn $RoleArn `
  --app-specification "ImageUri=$Image,ContainerEntrypoint=python,ContainerArguments=-c,from pricing_decision.offline.pipeline import OfflinePipeline; from pricing_decision.orchestrator import PricingOrchestrator; OfflinePipeline(PricingOrchestrator()).run('ol_ope', {'estimator': 'dr'})" `
  --processing-resources "ClusterConfig={InstanceCount=1,InstanceType=ml.m5.large,VolumeSizeInGB=20}" `
  --processing-output-config "Outputs=[{OutputName=ope,S3Output={S3Uri=s3://$Bucket/gold/ope,LocalPath=/opt/ml/processing/output}}]"

Step 9

Model Registry and the gate

Create a model package group once. Each successful night creates a package with the causal artifact, the bandit artifact, the OPE JSON, and the version pins. Approval is the gate you already coded: DR better than current, lower CI above current, ESS ok, fairness ok, latency budget ok. If the gate fails, the package stays Pending and checkout keeps the old pins. If it passes, mark it Approved and only then tell the online host to take policy_id / causal_model_id.

aws sagemaker create-model-package-group --region $Region `
  --model-package-group-name pds-pricing-policies `
  --model-package-group-description "Causal + bandit pins for the Pricing Decision Service"

# After a training job finishes and OPE JSON is on S3, register (fill the ModelDataUrl):
# aws sagemaker create-model-package --model-package-group-name pds-pricing-policies `
#   --inference-specification file://infra/sm-package.json

In Python, offline/registry.py should call create_model_package instead of writing models.json when PDS_ENV starts with aws. offline/gate.py stays the same checks. It only changes where it reads the OPE blob and where it writes Approved versus Staging.

Step 10

One nightly SageMaker Pipeline

Once the individual jobs complete by hand, wire them so you cannot run train before backfill. SageMaker Pipelines is the DAG: ingest → join → backfill → causal and bandit in parallel → OPE → fairness → drift → condition (gate) → register. Schedule it with EventBridge at a quiet Canadian hour. Failed pytest in CI must not update the image the pipeline uses.

# After you add infra/sm_pipeline.py (uses sagemaker.workflow):
# pip install sagemaker boto3
# python infra/sm_pipeline.py   # upserts the pipeline
# aws sagemaker start-pipeline-execution --pipeline-name pds-offline-nightly --region ca-central-1

A minimal pipeline script creates ProcessingStep objects whose command is still OfflinePipeline(PricingOrchestrator()).run("ol_…"). That is the whole point: SageMaker hosts the stages you already have. Studio is optional. You can do every step from the CLI and the console Jobs list.

Step 11

How the model gets back to FastAPI

Do not create a SageMaker endpoint for /v1/price. Checkout needs guardrails, coupons, stickiness, and a 100 ms budget in one process. After the package is Approved, write the new pins to AppConfig or SSM and have stage 10 hot-reload, or roll a new ECS task / Container Apps revision that loads the artifact from S3. Shadow means the new revision logs and does not serve. Then 1%, 5%, 25%, 100%. If CloudWatch says p99 or 5xx is wrong, put the weight back to zero.

A SageMaker endpoint is a later split if you want μ scored in a separate service. Even then, the bandit, the legal arm set, and the experience log stay in FastAPI. Training never runs inside the online task.

Step 12

What done looks like

You have implemented this project on SageMaker when all of the following are true. A Processing job has written silver training rows joined on decision_id, not customer_id. A backfill job used features as of the decision timestamp. A Training job produced a causal artifact and a bandit artifact in ca-central-1. An OPE job wrote DR, IPS, SNIPS, a bootstrap interval, and ESS under gold/ope. The Model Registry has a package that is Approved only because the gate passed, or Pending because it did not. FastAPI still answers POST /v1/price in tens of milliseconds with the new pins after a canary, and holdout traffic still exists. pytest still passes on a laptop against local JSONL.

aws sagemaker list-processing-jobs --region ca-central-1 --max-results 5
aws sagemaker list-training-jobs --region ca-central-1 --max-results 5
aws s3 ls s3://$Bucket/gold/ope/
aws sagemaker list-model-packages --model-package-group-name pds-pricing-policies --region ca-central-1

Stop signs

What not to do

Do not train on the online FastAPI container. Do not start by wrapping /v1/price in a SageMaker endpoint. Do not use us-east-1 for the lake. Do not train on the current customer profile instead of the features as of the decision. Do not register a model because the training job status is Completed — Completed only means the process exited. Do not explore in production if the decision log is not landing in bronze; stop exploring and buffer. Do not leave an ml.p3 instance running after a failed job. Do not rewrite the causal or bandit stages to “be SageMaker.” Swap the lake and the registry.
